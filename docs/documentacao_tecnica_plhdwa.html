Despachante (1 execução = 1 lote) · src/despachante.py

Job

plhdwa_despachante · File arrival em ctl/ (1 execução por vez, com fila); também disparado pelo vigia.

Papel

Orquestra o lote: lê a pasta, decide o que roda e onde, processa os objetos do modo DESPACHANTE em threads e dispara jobs independentes para os objetos do modo JOB. Termina quando não há pendente nem nada rodando.

  1. Lê os parâmetros (COMUNS + ciclo_s, max_horas, max_threads) e inicia o motor (iniciar); o lote é o próprio job_run_id.
  2. Fecha lotes órfãos (fechar_lotes_orfaos) e registra INICIADO em log_lote.
  3. Laço até max_horas: a cada ciclo_s faz o ciclo completo (relê ctl_execucao, os jobs ativos e a pasta; trata jobs que terminaram; grava as fotos do ciclo).
  4. Entre ciclos, despachar() preenche as vagas livres: cadeia mais longa primeiro, no máximo 1 arquivo por objeto, respeitando o max_simult de cada modo.
  5. Espera a 1ª thread terminar (wait(FIRST_COMPLETED)) ou a hora do próximo ciclo: a vaga é reaproveitada na hora.
  6. Fim: registra FINALIZADO no log_lote; se houve erro, termina a execução como FAILED (para a notificação do Jobs avisar).

plhdwa_carga_arquivo_perf · plhdwa_carga_arquivo_std · run_now do despachante, com ctl, modo e lote_id.

Papel

Processa o arquivo recebido e segue com os próximos arquivos do mesmo objeto, em ordem de geração, até max_arquivos ou max_minutos (o arranque do job é pago uma vez por objeto). Existe um job por tipo (Performance Optimized e Standard).

  1. Lê os parâmetros e inicia o motor; o lote_id vem do despachante.
  2. Proteções contra nova tentativa automática: sai se o arquivo já está CONCLUIDO; falha se o objeto está travado (sem fazer nada).
  3. processar_arquivo do CTL recebido.
  4. Laço: enquanto houver arquivo pendente do objeto (pendentes(cod)) e não bater os limites, processa o próximo (com ROTEADO gravado junto do INICIADO).
  5. Qualquer erro sobe e a execução termina FAILED; o despachante registra ERRO_EXECUCAO no arquivo que ficou em aberto, se não houver evento final.

8Comandos da controle no Db2 (só UPDATE)

Arquivo sql/<db2_comando>, editável pelo DBA: uma seção por status, cada uma com um UPDATE e os dados do arquivo como marcadores :nome (ler_comandos_db2). O motor recusa qualquer outro comando; 0 linhas atualizadas = ERRO_DB2.

-- [CONCLUIDO] (carga OK) e -- [ERRO] (obrigatórias);
--     -- [EM_PROCESSAMENTO] só é usada com db2_registrar_inicio = true;
--   * {tabela} = variável db2_tabela (ex.: ctl.OBJETO_DEPENDENCIA_EXECUCAO);
--   * dados do arquivo como marcadores :nome  ->  :cod_objeto :nome_tabela :data_movimento :data_geracao
--     :instituicoes :lista_cd_inst :status :qtd_registros :arquivo :job_run_id :lote_id :modo_execucao :dt_inicio
--     :dt_fim :mensagem
--   * :lista_cd_inst = cd_inst do CTL para usar em IN (...): "1,2,3" vira IN (1, 2, 3); "0" (todas) vira IN (0), ou seja,
--     a linha com CD_INS = 0; erro antes de ler o CTL (cd_inst desconhecido) também usa 0;
--   * UPDATE que não encontra linha (0 linhas) = ERRO_DB2 no arquivo, com a mensagem; mais de 1 linha é aceito.
-- :mensagem chega com até db2_mensagem_max caracteres (padrão 500): ajuste ao tamanho de DS_MNG_ERR_EXC.
-- =====================================================================================

-- [CONCLUIDO]
/* Sinaliza CTL DB2 em caso de carga OK */
UPDATE {tabela}
   SET IC_PRC_EXC = 0,              /* 0 indica que o processo não está mais em execução */
       IC_PRC_FNZ = 1,              /* 1 indica que o processo finalizou com sucesso */
       DH_FIM_PRC = CURRENT TIMESTAMP
 WHERE CD_OBJ IN (CAST(:cod_objeto AS INTEGER))
   AND CD_INS IN (:lista_cd_inst)   /* instituições do cd_inst do CTL (0 = linha de todas) */

-- [ERRO]
/* Sinaliza CTL DB2 em caso de erro */
UPDATE {tabela}
   SET IC_PRC_EXC = 0,              /* 0 indica que o processo não está mais em execução */
       IC_PRC_FNZ = 0,              /* 0 indica que o processo finalizou com erro */
       DH_FIM_PRC = CURRENT TIMESTAMP,

ferramentas/converter_ddl_netezza.py

Converte a DDL de uma EXTERNAL TABLE do Netezza em:
  1) CREATE TABLE da tabela Delta de destino (layout: colunas, ordem e tipos; CLUSTER BY; tag OWNER);
  2) MERGE da linha do objeto na ctl_parametros (tabelas operacionais do PLHDWA): destino, tipo de carga, colunas
     do REPLACE WHERE, modo de execução, formato do arquivo e limpeza.
O motor não usa tags nem TBLPROPERTIES plhdwa.* (07/10/2026): tudo o que é parâmetro fica na ctl_parametros.
O formato do arquivo (delimitador, header, encoding, escape...) é lido do bloco USING da DDL
do Netezza, que é quem gera o .dat. Assim, os dois lados nunca ficam diferentes.

Uso (local, só Python 3, sem dependências):
  python3 converter_ddl_netezza.py exemplos/ddl_external_dwa_ccr_fatparcela.sql       --catalogo <catalogo_destino> --schema <schema_destino> --tabela fat_parcela       --catalogo-controle <catalogo_plhdwa> --schema-controle <schema_plhdwa>       --cod-objeto 1230 --filtro-tabela SIM --nome-coluna-tempo SK_TMO_MVM --nome-coluna-instituicao NR_CPR       [--execucao DESPACHANTE|JOB] [--tipo-job PERFORMANCE_OPTIMIZED|STANDARD] [--owner-tag PLHDWA]       > 1230_fat_parcela.sql
--catalogo-controle/--schema-controle = variáveis catalogo e schema do bundle (onde está a ctl_parametros).
